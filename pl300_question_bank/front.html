How to use these sets

Each set is one sitting of the exam. Give yourself 100 minutes, answer every question before you look at the key, and mark anything you guessed. The answer key for each set follows it immediately. Every question has a sub-area tag, so you can see where your marks went. Then comes an explanation that says why the right answer is right and why the others fail.

Scoring

The real exam is scored 1–1000 with 700 to pass. The score is scaled, so it doesn't map to a fixed number of questions. These sets use a stricter rule of thumb: 34 out of 45 (75%). Score multi-part items fractionally. Two sets in a row at 75% or more, on sets you haven't seen, is a good sign you're ready to book.

Exam-day reminders the sets are built to train

  • Find the constraint before reading the options. Look for phrases like minimise administrative effort, without modifying the semantic model, least privilege, the data must not be copied, minimise the size of the model.
  • Reference shares upstream steps; duplicate copies them. Clear Enable load on staging queries.
  • Import is the default storage mode. DirectQuery for near-real-time or data that must stay in the source. Direct Lake when the data already sits as Delta tables in OneLake.
  • A date table must be marked, have unique, contiguous dates and cover whole years. Inactive relationships are used with USERELATIONSHIP.
  • Edit interactions stops one visual filtering another. Sync slicers shares a slicer across pages. Drillthrough with Keep all filters carries the context.
  • RLS restricts Viewers only. Admin, Member and Contributor bypass it. Roles are written in Desktop and members are assigned in the service.
  • Data alerts live on dashboard tiles. Subscriptions email snapshots. Publish to web is public, so it's never the answer for internal data.
  • Scheduled refresh: up to 8 a day on Pro, 48 on Premium or Fabric capacity. A personal-mode gateway is single-user and Import only.
